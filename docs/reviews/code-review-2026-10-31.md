## Original findings and evidence (read with the current disposition above)

1. **Blocker · Fix now · security — anyone can rewrite scores and control the contest under the shipped rules.** [database.rules.json](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/database.rules.json:3) grants unconditional writes to the question bank, active-session pointer, join codes and sessions. There is no identity or shape validation. Someone with the displayed session ID can change the phase, another player's score or answers. Accept Claude B1 based on direct source inspection; the installed production rules remain unknown. Require a real admin identity, authenticated player identity, deny-by-default rules, and create-once answers constrained to the current question/deadline. Verify allow and deny cases in a Firebase emulator before rollout.

2. **Blocker · Fix now · security — built-in passwords and browser storage bypass Firebase admin authentication.** [authService.ts](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/services/authService.ts:53) returns an admin for hardcoded passwords even when Firebase is configured; stored local-admin data is also trusted. The parent probe returned `admin_master` with zero Firebase sign-in calls. Accept B2. Restrict demo login to explicit local mode and use Firebase Auth for configured deployments. Ship this together with the rules change; tightening rules alone would leave these fake admin sessions unable to write.

3. **Blocker · Fix now · security — players receive the answer key before reveal.** Full question objects are stored in [gameService.ts](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/services/gameService.ts:87) and delivered by its [whole-session subscription](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/services/gameService.ts:437); the rules also allow public bank reads. The local probe read all 20 correct-answer indices without authentication. Accept B3. Keep keys in an admin-only location and publish the current answer/explanation at reveal; avoid placing real contest answers in the public bundled defaults. Write restrictions alone do not fix this read exposure.

4. **Blocker · Fix now · bug — reveal is not atomic or safe to repeat.** [Firebase revealAnswer](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/services/gameService.ts:285) calculates absolute totals from the caller's snapshot and writes without checking the current server phase/question. A delayed host can overwrite newer scores; a repeated reveal using updated totals awards the same points again. [Local performReveal](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/vite-plugin-quiz-sync.ts:76) has the same repeated-award defect: the actual backend probe changed 1,500 to 3,000 for one answer. Accept B4 and this part of R5. The stale Firebase-device timing is source-reasoned, not reproduced against Firebase. Score exactly once against authoritative state with expected phase/question checks; protect start/next transitions too. The redesign removes the redundant local host auto-reveal, but that does not make the endpoint safe to repeat.

5. **Blocker for real-event local mode · Fix now · bug/security — future answers are accepted, and rejected submissions can look successful.** The [answer endpoint](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/vite-plugin-quiz-sync.ts:301) checks phase/deadline but not whether the supplied question ID is current. The parent submitted q2 during q1 and later received the full 1,500 points for q2. Separately, [submitAnswer](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/services/gameService.ts:396) turns an HTTP 400 into a successful local-cache write; reproduced with the real service and a stubbed transport. Accept R5 plus the independently found future-question case. Validate current question, answer range, player identity and create-once semantics at the authority; surface rejection to the player. Local API controls are unauthenticated and state is in memory, so keep this mode for demos until deliberately hardened.

6. **Recommended · Fix now · bug — Firebase timing can unfairly score or omit answers.** [submitAnswer](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/services/gameService.ts:384) records the phone's `Date.now()` while question start uses a server timestamp. Clock skew therefore changes the bonus. The [host's deadline reveal](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/components/admin/AdminDashboard.tsx:68) scores its current snapshot immediately, so an in-time answer not yet received by that host can be omitted. Accept R1/R3 mechanisms, without Claude's unmeasured frequency claim. Use authoritative answer timestamps and an explicit deadline/grace policy with authoritative scoring. Countdown offset correction is Recommended · Defer until the same timing work. No latency or clock-skew runtime measurement was made.

7. **Recommended · Defer · bug — reopening the join link in another tab can create a second player.** [JoinScreen.tsx](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/src/components/player/JoinScreen.tsx:33) restores from sessionStorage, so ordinary refresh is supported. A new tab/browser or timed-out join retry can create another record and leave the old score behind. Accept R4 narrowly; do not report refresh itself as broken. Resume a per-session authenticated player identity when implementing the rules/identity work.

8. **Recommended · Defer · test_gap — old test scripts do not test production game logic.** [test-game.js](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/scripts/test-game.js:44) and [test-user-scenario.js](/Users/abdelmawla/Developer/Codex/aou-icpc-quiz-game/scripts/test-user-scenario.js:21) copy the algorithms; their pass banners do not prove service or rule correctness. Accept R6 for those scripts. The redesign now adds `npm run test:admin`, which exercises actual services and local middleware, so a claim of no real service tests is outdated. Add emulator authority tests and exactly-once scoring/reconnect cases with the corresponding fixes; retire or clearly label copied simulations.
